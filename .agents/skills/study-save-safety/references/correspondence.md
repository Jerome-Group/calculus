## Queue actions

The data shape follows `Entry` and `Edit` in `lib/study/session.ts`. Model edit integers stand for a unique mutation ID together with its normalized payload. Equality checks therefore cover both fields. `seq` is the local edit order. `local` is the visible payload token. `pending` and `flight` contain an edit token or zero. The confirmed revision and edit token describe the last installed record. `acknowledged` and `conflictHeld` are observation history used by the properties, not extra product fields.

## Read actions

The model retains the state changed by `responseOwner`, the overview request guard, and identity invalidation. A payload's owner label stands for a schema-valid personal value from that owner. The numeric overview value is a distinguishable summary snapshot, not a grade.

| `DeliverRead` request-ID guard | `loadOverview` line 295 ignores an older request after any newer overview was issued, even if the newer request has not completed.                                                                                                                 |
| `DeliverRead` owner guard      | `responseOwner` lines 239–246 rejects another owner's response, clears private entries, and immediately starts revalidation. `invalidate(true)` followed by `validate`'s `invalidate(false)` increments epoch twice before the new identity await. |

The read model is an abstraction of valid lesson and overview reads. It does not model write responses, history, attempts, imports, guest mode, identity failure, or every validation request. It assumes the independent generation check in `validate` prevents an obsolete identity response from installing identity. Replacing an outstanding identity request in the model discards its old response under that assumption. The `EpochIsolation` claim here covers lesson and overview delivery, not that assumed identity guard.

`EpochIsolation` records an effect when an obsolete read takes an install or owner-invalidation branch. `LatestOverviewWins` records an install by an obsolete overview ID. These history flags express the forbidden transition. `ResponseOwnerIsolation` checks the owner of visible data. Removing each guard independently produces a TLC counterexample and a real-code failure.

## Exact finite scope

| Bound                | Value                                                                                                                                                                                                                      |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Queue account        | One already verified, visible account.                                                                                                                                                                                     |
| Queue keys           | One `assessment` and one `practice-draft` in one loaded lesson.                                                                                                                                                            |
| Local edits          | At most two per key, each a distinct normalized payload and mutation ID.                                                                                                                                                   |
| Initial records      | Assessment revision 1 and draft revision 0. Both are loaded.                                                                                                                                                               |
| External writers     | One successful competing assessment write, at any permitted point.                                                                                                                                                         |
| Concurrent flights   | At most one per key, as in `pump`. Different keys may overlap.                                                                                                                                                             |
| Overview requests    | At most four, the maximum acknowledgements for four distinct local edits in this scope. Each has independent request, snapshot, response, and completed states.                                                            |
| Failures             | Any request may fail before server acceptance or lose its response after acceptance. Retries reuse the same edit identity. Repeated loops are state revisits.                                                              |
| Read owners          | `A` and `B`. No guest owner.                                                                                                                                                                                               |
| Read requests        | Two slots, each independently lesson or overview.                                                                                                                                                                          |
| Cookie changes       | At most one, from `A` to `B`.                                                                                                                                                                                              |
| Validation           | One explicit revalidation, plus the bounded mismatch revalidations caused by the two read replies.                                                                                                                         |
| Read state values    | Epoch starts at relative zero and reaches at most eight. Owner labels are `none`, `A`, or `B`. Overview IDs reach two. Summary tokens are zero, one, or two. Equality and order, not absolute production counters, matter. |
| Search               | Exhaustive BFS, one worker, fixed fingerprint selector 0 and seed 1, 512 MiB maximum heap. No random simulation or depth truncation.                                                                                       |
| Temporal obligations | Safety invariants only. No fairness, eventual save, or network recovery theorem. Deadlock checking is disabled because exhausted bounded input is intentional.                                                             |

The checked state graphs are finite. The historical baseline queue pass explores 37,353 distinct states. The read pass explores 2,035. The maintained run records its current counts in `summary.json`. These counts identify these exact models and configuration, not the size of the production state space. TLC uses 64-bit state fingerprints and reports its collision estimate in every full pass log. No theorem for unbounded edits or requests follows.

The models are separate bounded checks, not a composition proof. The queue excludes account changes, unloaded entries, explicit conflict resolution, and null deletion values. The read model excludes the write queue. The queue's revisions reach at most four for assessment and two for draft. Existing initial payloads and UUIDs are opaque equality tokens.

## Real-code correspondence checks

`scripts/bridge.mjs` reuses the Vite SSR loading pattern from `tests/study-account-session.test.mjs`. It imports the actual source and real schemas. A small controlled HTTP service supplies schema-valid record, conflict, and owner replies. It deliberately ignores the passed abort signal so a late response can still arrive. That is the adversarial behavior the epoch guard must tolerate.

Seven scenarios check the seven promises. The queue error traces emitted by TLC are also replayed automatically. The replay compares every supported state against actual visible values, persistence states, and server records. Unsupported transitions fail with an instruction to extend the replay from real code. This is trace conformance for these paths, not a full refinement proof or a generated model of TypeScript execution.

The shortest baseline retry counterexample is even smaller than the unrelated-draft reproduction. A successful assessment edit starts an overview. Before the overview reads its row, a second assessment edit fails. The old request then reads the unchanged confirmed revision and installs it. `unsaved` becomes `saving` with no flight. The conflict trace uses that same delayed overview after another writer causes a 409. Both exact traces replay against the real source. The separate named reproductions cover the original unrelated-draft triggers.

`setImmediate` in the controlled service lets already resolved promise continuations finish. It does not wait a fixed wall-clock interval for external readiness. Gates and observed conditions control delayed requests.

## Excluded guarantees

SQL correctness, D1 isolation, concurrent server transactions, authenticated gateway behavior, UUID collision freedom, cryptographic authorization, schema correctness, oversized or invalid values, all record kinds, imports, attempts, history, account-leave recovery, reload persistence, offline durability, storage quotas, React rendering, browser focus events, cross-device continuity, and learner outcomes are outside these checks. Server CAS and owner scoping are read as assumptions, not formally verified here. Browser verification and the built Worker tests remain necessary for their respective claims.
